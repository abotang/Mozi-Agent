# 任务规则目录

这里放可复用、可测试的**任务专用确定性规则**。Agent 依据态势决定任务意图和参数；本目录校验边界并生成脚本需要的确定值。

| 文件 | 作用 |
| --- | --- |
| `__init__.py` | 规则包标记；具体逻辑都在下列模块 |
| `awacs_area.py` | 识别预警机并选择最近蓝方机场/航母，按预警机 Agent 的轴向和前推距离生成跑马道，校验全部区域点在 300 km 内 |
| `awacs_deployment.py` | 读取本项目已有预警任务的站位，限制同时最多两架，并按当前战场跨度计算双机最小间距 |
| `awacs_triggers.py` | 根据想定时间、预警机起降状态与敌机距离，决定何时调用预警机 Agent；校验开局、区域调整、回撤与换班 |
| `threat_axis.py` | 当前仅有一架敌方预警机接触时，计算蓝方平台指向该接触的疑似空中进攻轴向；不生成未探测的敌机或打击目标 |
| `agent_activation.py` | 无本 Agent 单元、无可用 Skill、全是打击 Skill 却无对应实时接触时，跳过专业 Agent 模型调用 |
| `air_patrol_update.py` | 仅将本项目原战斗巡逻任务中的飞机交给空军 Agent 改区；校验原任务 GUID、名称、Skill 和完整飞机编组，防止占用机进入新任务 |
| `side_doctrine.py` | 新想定开局或想定时间倒退时触发一次蓝方推演方接战临机目标设置 |
| `joint_refresh.py` | 联合指挥方案的战略变化快照：新想定、蓝方兵力变化、威胁类别出现或消失、威胁距离段跨越时立即刷新；其余情况受刷新间隔控制 |
| `situation_memory.py` | 用确定性代码压缩当前想定的接触轨迹、接近趋势、距离段事件和已校验方案；记录有固定上限，保存在 `automatic_state.json`，没有额外 LLM 调用 |
| `situation_refresh.py` | 同 GUID 接触自上次规划移动 ≥40 km 且间隔 ≥30 秒现实时间，或跨越 300/150/75 km 距离段时，提前唤醒规划 |
| `navy_patrol.py` | 舰艇海上巡逻仅在想定开局可调用 |
| `jammer_support.py` | 飞机打击任务出现后选择空闲干扰机，计算主攻机群后方伴随航点与刷新时机 |

新增规则先写成独立函数，再由 `runtime/planning/` 或 `runtime/app/` 调用。`runtime/planning/validation.py` 保留所有任务共用的 GUID、军种归属、目标类别和重复分配校验。固定脚本只执行已经校验的任务参数。

态势记忆最多保存 80 个接触、每个 10 个位置采样、30 条事件、6 份已校验方案和 16 条脚本下发结果；实际交给联合指挥的视图最多 12 条活动轨迹、6 条事件、3 份方案和 8 条下发结果。专业 Agent 只收到相关类别的至多 7 条轨迹。丢失接触只记为历史事件，不能作为新打击任务的目标。想定时间倒退时清空旧轨迹，避免把上一局数据混入新局。方案历史不是执行结果；脚本下发结果也不等于战果或目标毁伤。
