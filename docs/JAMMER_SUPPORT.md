# 飞机打击任务的电子干扰伴随

这项能力由 `rules/jammer_support.py`、`runtime/execution/jammer_controller.py` 和固定脚本 `scripts/powershell/09-电子干扰伴随.ps1` 实现。它不调用 LLM 编写脚本，也不依赖旧 LLM+BT 项目或墨子任务界面的护航标记。

## 触发与选机

自动推演创建对空、对海或对地的**飞机打击任务**并取得任务 GUID 后，控制器立即回读该任务。只有回读到真实打击目标与已分配主攻机时才派机。一项打击任务最多预留一架空闲干扰机；候选机必须在设施中、没有分配给任何墨子任务，并且 `unitSensors` 能回读到雷达与电子干扰设备。没有符合条件的飞机则保持待命，下次轮询再检查。

已识别的干扰机不进入空军 Agent 的 `own_units`；空军 Agent 生成的主任务或护航 GUID 必须属于该列表。统一方案校验还会拒绝任何普通空军任务的主单元或护航字段引用干扰机，因此直接提交任务方案也不能绕过。识别目前依据飞机名称/型号中的干扰机标记；新型号若未命中，应先在 `rules/jammer_support.py` 补充标记。

## 出动与伴随

派机时立即用 `singleOperation` 请求起飞。请求成功仅表示墨子接受了出动指令；控制器持续看实时态势，确认升空后才发送设备和航点指令。干扰机用 `PlottedCourse` 飞往主攻机群后方的点，默认相距 20 km。后方按主攻机群已观察到的移动方向计算；方向未确认时先开启设备、等待移动，不猜测后方。主攻机移动至少 5 km 或达到配置的刷新间隔后重新计算航点。

升空后固定脚本解除主动辐射限制，请求开启雷达 `RADER=true` 和电子干扰 `OECM=true`，再回读传感器。回读确认 EMCON 已关闭；雷达与干扰设备的实际辐射状态取决于墨子接口回读，不能仅凭请求成功断言已持续工作。任务消失、主攻机长时间未出动或想定结束时，脚本请求关闭两类设备；已在空中的干扰机还请求返航。

## 配置与记录

`config/deployment.json` 的 `jammer_support` 可以调整开关、尾随距离、航点刷新间隔、起飞重试间隔和最长等待想定秒数。每个打击任务与干扰机的绑定状态保存在 `runs/automatic_state.json` 的 `jammer_support` 字段；脚本输入与事件在 `runs/jammer_support/`。新想定开始时清除旧绑定。

这一逻辑只在自动推演入口执行。墨子任务列表中仍是原来的打击任务；干扰机由独立脚本控制，不会新增一个护航任务。若需要核实实际出动，请同时看实时态势里的干扰机位置与 `runs/jammer_support/events.jsonl`，不能只看脚本返回的成功标志。
