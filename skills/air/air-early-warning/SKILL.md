# 空中预警

预警机 Agent 选择一架蓝方预警机，并根据当前态势决定进攻轴向与向前延伸距离。本地规则把**该机当前位置最近的蓝方机场或航母**作为起飞平台；选择依据和平台 GUID 会写入区域备注。不能把战斗机分配给此任务。

默认只安排一架预警机。若已有预警任务能覆盖当前方向，不新增重复任务。只有 Agent 判断战场范围很大、单机无法兼顾两个独立方向时，才安排第二架，并在 `reason` 写明可观察的态势依据和各机负责的扇区。两架及已有任务的区域中心须按 `operational_rules.awacs_min_separation_km` 拉开；规则层最多接受两架，并拒绝重叠站位或同一架预警机重复出动。挑选时参考燃油、损伤和现有任务，尽量保留轮换机。

Agent 的 `area` 输入只包含部署决策，不手写多边形点：

```json
{"pattern":"racetrack","attack_bearing_deg":45,"forward_km":180}
```

`attack_bearing_deg` 为从起飞平台朝向进攻方向的方位角，0° 为北，90° 为东。`forward_km` 是从平台沿该轴向到跑马道中心的距离。两项同时填写，最长 **284 km**。没有已知空中进攻轴向时，只填 `{"pattern":"racetrack"}`；区域中心留在平台附近，长轴暂按东西向。

跑马道整体外形为**长 60 km、宽 30 km**：中间直线段 `L=30 km`，两端半圆半径 `r=15 km`；长轴始终与所填进攻轴向垂直。连续轮廓的几何上限约为中心前推 **284.6 km**，本规则取 **284 km** 留出坐标计算余量，并逐点校验离起飞平台不超过 **300 km**。区域不合规则拒绝创建，不静默缩小或更改 Agent 的部署决定。

本 Skill 创建墨子 Support 任务、支援区域和单位分配，不选择打击目标；固定脚本启用“1/3规则”（`OTR=true`）。若多架预警机需要不同阵位，分别调用本 Skill。

## Agent 触发与原任务更新

本 Skill 的 `agent_owner` 是 `awacs`，空军战斗机 Agent 看不到也不能调用。调用时机由 `rules/awacs_triggers.py` 根据实时态势决定，规则结果放在 `operational_rules.awacs_trigger`：

- `opening`：开局无敌情时平台附近、东西向；已有敌情时按进攻轴向保守前推。
- `local_to_threat`：开局本地任务满 20 分钟后，有敌方空中接触才更新原任务区域；没有敌情继续原区域。
- `threat_retreat`：敌机距在空预警机 300 km 内，沿进攻轴向缩小 `forward_km`；可为负值，允许区域退到原起飞平台后方，且新区中心必须离触发敌机更远。
- `relief`：只有本项目观察到该机曾在空、现在位于机场/航母内部时，才让备用预警机接替。调用时复用 `existing_mission_guid`、任务名与区域，`parameters.relieved_unit_guid` 写返航飞机 GUID；固定脚本先移除旧机，再分配新机。

更新任务必须保留原起飞平台 GUID，不能因为飞机飞远而改选更近的平台。每次成功更新后记录想定时间与区域部署参数，供下一轮规则判断。若墨子返回结果不确定，自动循环停止重复提交同名预警任务，等待核对。

区域参考点形成跑马道形状；墨子是否让飞机沿该轮廓持续飞行，需要在推演中观察轨迹。任务区域和真实飞行航线是两个不同对象。
